## 本轮范围

本轮需求范围按用户指定的呈现方式调整为：模拟银行卡绑定、交互式已绑定卡片列表、逐卡余额隐藏与显示、点击卡号发送详情、密码验证后查看完整卡号；同时保留中文状态归一化、非法筛选保护、空结果、用户隔离和完整验收要求。保持现有五层架构。新增数据和接口能力见“数据与契约缺口”，实施时按仓库规则单独记录契约变更。

不包含按卡类型、尾号、额度筛选，也不增加分页、排序参数、挂失/锁定/调额等卡片写操作或直接执行选卡后的业务。绑定仅写入 Agent 的绑定关系，不改变银行卡状态或账户余额。向 F05–F09 提供现有 card_id 和脱敏信息；选卡交互与其他写流程由对应功能负责。

连续追问作为建议扩展项单列，见下文。此草案不将其视为已批准的实现范围。

## 模拟银行卡绑定

用户已确认增加模拟绑卡：预设合成银行卡、关联账户余额和每卡密码；用户输入卡号与密码，通过验证后将该卡绑定到 Agent。绑定验证的条件是卡号存在、密码正确、归属匹配，余额不作为成功条件。

### 预设数据与绑定关系

- 合成卡片保存完整模拟卡号、对应脱敏卡号、所属 user_id、关联 account_id、卡类型和状态；模拟银行卡密码仅保存加盐哈希。
- 余额保存于关联账户，不为绑卡表另存一份余额。多卡关联同一账户时，共享该账户余额。
- 新增独立绑定记录，至少关联当前用户与 card_id，并记录绑定时间；用户与同一卡片的组合唯一。
- 卡片归属表示“这张卡属于谁”，绑定记录表示“用户已把这张卡加入 Agent”，两者不能混用。绑定不能修改原卡归属，也不新建卡或账户。
- 新演示环境的卡片预设但未绑定，以支持完整绑卡演示。已有演示数据的兼容策略在实现时单独确定，不能自动重置现有数据库。

### 用户流程

1. 点击“绑定银行卡”；未绑定任何卡时，列表空状态也提供该入口。
2. 在独立表单输入模拟完整卡号与该卡的模拟银行卡密码。密码输入遮蔽，卡号和密码不发送给模型、不追加到聊天文本。
3. 用户点击“确认绑定”，该操作作为对添加这张卡的明确确认。
4. 服务端校验格式、卡片存在、卡片及账户归属、密码和重复绑定情况；通过后在事务内保存绑定关系并记录审计。
5. 返回脱敏成功提示并更新列表。余额按关联账户读取、默认隐藏；绑定成功不直接展示完整卡号或明文余额。

### 成功与失败规则

- 卡号可以输入连续数字或分组空格，由确定性代码去掉分组空格后查找。当前演示卡号为十六位；不得把掩码卡号用于绑定。
- 密码正确但卡片属于其他用户时拒绝绑定，不泄漏其他用户的卡片信息或余额。
- 不存在的卡号、密码错误、归属不匹配均使用“卡号或密码不正确，或该卡不可绑定”的统一失败提示；失败不新增绑定记录。
- 重复提交或重复绑定当前用户的同一卡，返回已绑定提示，不插入重复行；并发请求也由数据库唯一约束保障。
- 输入格式错误可以明确指出卡号或密码格式问题，不能在日志中输出输入值。
- 取消或验证结束后清空敏感输入。密码错误限次与恢复规则由服务端确定；具体参数在实现方案中定案。
- 余额读取暂时失败不代表绑卡验证失败：绑定状态保留，余额显示“暂不可用”并可重试，不显示零元。
- 挂失、锁定、冻结卡是否允许绑定需明确规则；建议允许展示绑定并保留原状态，绑定本身不使卡恢复可用。
- 完整卡号查看仍需重新输入该卡密码；绑卡成功不能作为持久的完整卡号查看授权。

### 与查询的衔接

用户界面“我的卡片”默认显示当前用户已绑定的卡，状态筛选也只针对这些卡。无绑定时提示“您还未绑定银行卡”并提供绑定入口；有绑定但筛选无结果时保留原有筛选空状态文案。

既有 T18 `list_cards` 的“查询全部归属卡片”冻结语义保持不变。新增 Agent 已绑定卡片查询能力负责用户列表，避免悄然改变其他功能依赖的工具语义。是否提供解绑另立需求，本次不自动加入解绑操作。

## 用户指定的列表和详情交互

### 三列卡片列表

当用户询问“我有哪些卡”“查询我的卡片”等查询请求时，在聊天中展示当前用户已绑定卡片的交互列表。用户明确指定状态时，展示已绑定卡片中的对应筛选结果，并标明当前筛选状态。

| 卡号 | 状态 | 余额 |
| --- | --- | --- |
| 6222 **** **** 0001（可点击） | 正常 | ******（右侧闭眼按钮） |
| 6222 **** **** 0003（可点击） | 已挂失 | ******（右侧闭眼按钮） |

以上为合成卡号的布局示意，实际列表来自工具查询。三列顺序固定为卡号、状态、余额。掩码格式为前四位与后四位可见，中间八位为星号，分组显示成 `前四位 **** **** 后四位`。卡号使用可聚焦、可点击的链接或按钮样式，避免仅靠颜色暗示可操作。

### 余额眼睛按钮

- 每张卡的余额默认显示固定占位 `******`，右侧为闭眼图标；占位长度不透露金额位数。
- 点击该行闭眼按钮后，仅该行显示真实账户余额，眼睛变为睁开；再次点击恢复星号及闭眼。
- 行间状态互不影响，不设置默认“全部显示”。余额显示不要求输入密码；密码仅用于下文的完整卡号查看。
- 新查询结果、页面刷新、会话重置或用户切换后，所有行恢复隐藏。界面正常重绘时保留当前结果内的逐行显示状态。
- 按钮具有“显示余额”/“隐藏余额”的可访问名称，支持键盘操作；同一行的余额切换不触发卡号详情点击。
- 真实余额不写入默认聊天文本、隐藏时的提示气泡或可访问标签。隐藏功能用于防止旁观者直接看到，不等同于密码授权。
- 加载失败时显示“余额暂不可用”与重试入口，不伪装成零元；没有余额权限时不能通过眼睛按钮获得数据。

### 余额来源与含义

建议第三列展示卡片绑定账户的 `balance`，以人民币元、两位小数显示，金额事实保持整数分。不得将信用卡授信额度或 available 字段冒充余额。

现有数据通过 card.account_id 关联 account。同一账户绑定多张卡时，各行展示相同账户余额，并在详情中说明“此卡关联账户余额”，避免误认为每张卡各自拥有独立资金。信用卡也使用账户余额，并明确区别于授信额度和可用额度；信用卡产品措辞需在审阅时确认。

### 点击卡号发送该卡详情

- 点击某行脱敏卡号后，在聊天中追加该卡的详情消息，保留原列表；按钮传递该行 card_id，不靠模型解析尾号选卡。
- 详情建议包含脱敏卡号、卡类型、中文状态、关联账户余额、适用的授信额度、单笔限额及日限额。当前数据没有的银行名称、有效期或开户信息不编造。
- 详情中的余额默认仍隐藏，具有独立眼睛按钮；普通详情消息不包含完整卡号或明文密码。
- 服务端重新验证卡片和关联账户都归属于当前用户。历史列表上的点击在用户切换后不能读取前一用户信息。
- 卡片不存在、已失去访问权限或请求失败时，给出明确提示，不展示其他卡作为替代。
- 详情中提供“查看完整卡号”操作；仅点击普通卡号不能直接显示完整卡号。

### 银行卡密码验证后查看完整卡号

- 用户点击“查看完整卡号”后，展示独立密码输入框，标签为“请输入此卡的银行卡密码”，输入内容遮蔽；不通过普通聊天消息收集密码，不发送给模型。
- 按用户确认，校验对象为所选银行卡自身的密码。每张卡独立绑定密码校验信息，不使用系统登录密码或另设全局查看密码。
- 密码验证必须在服务端完成，并绑定当前用户、会话及选中卡片。验证成功后，只在该卡的临时详情区域显示完整合成卡号，不追加到永久聊天文本；该卡验证成功不授权查看其他卡。
- 输入错误或取消时保持脱敏，不展示完整卡号；用户可主动关闭完整卡号，再次查看需要再次验证。
- 页面刷新、用户切换或会话重置后恢复脱敏，不能复用其他用户或其他卡片的验证结果。
- 普通卡片查询继续按 L0 审计；完整卡号验证和查看属于独立受保护流程，需定义对应权限与审计事件。记录结果及 card_id，不记录密码或完整卡号。
- 本项目是模拟银行，使用每张合成银行卡对应的模拟银行卡密码。校验信息以加盐哈希保存，不保存明文，不硬编码公共演示密码；密码位数、错误限次和恢复规则在后续契约设计中确定。
- 提交验证或取消后清空密码输入值；显示卡号期间不保留密码，以便关闭、刷新或切换用户后不能复用输入。

## 基线缺口与新增契约

基线 card 表只有 card_no_mask，没有完整卡号；不能从掩码反推出完整卡号。现有 T18 list_cards 返回的七个卡片字段也不含 account_id 或余额。本轮通过独立补充表保存完整合成卡号及密码哈希，新增已绑定卡查询、详情、预览/确认绑定和受保护卡号读取工具，保留 T18 原有契约。

新增函数、字段和错误规则记录在 SPEC CHANGE F01 文档中，不向冻结 CardItem 填入新字段。Web 入口使用新查询能力，原 CLI/API/IM 仍沿用既有 T18 行为。

- 卡片余额查询需要同时验证卡片和关联账户的归属，不按卡类型取一条账户余额替代绑定关系。
- 展示完整卡号需要新增独立保存的合成数据，确保与 card_no_mask 一致；只使用合成演示卡号。
- 密码校验信息不与普通卡片事实包合并；普通查询、润色、聊天记录及常规日志均不包含完整卡号和密码。
- 界面仍只调用 agent 层；由 agent 调度 tools/guard，再由工具读取 data，不从 Streamlit 直接访问数据库。
- 后续实现前需按仓库要求记录数据结构、工具契约与权限变化，并与共享模块集成人员协调；新增依赖须单独确认。

## 查询与状态规则

### 查询入口

- 面向用户的独立请求“我有哪些卡”“查一下我的卡”查询当前用户全部已绑定卡。
- 面向用户的独立请求“我有哪些挂失的卡”查询当前用户已绑定且符合对应状态的卡。
- 查询保持 L0 只读，不产生卡片状态、额度或资金变动。
- “帮我挂失这张卡”属于写意图，不得误判为状态查询或通过本功能执行。
- “有没有问题的卡”“不能用的卡”含义不明确，不自动等同于某一种状态；应澄清用户所指状态。

### 建议的中文状态映射

映射只在编排层理解和归一化阶段处理；工具直接调用仍严格接受既有英文枚举或 `None`，不改变签名和 schema。

| 标准值 | 建议接受的明确表述 | 用户显示 |
| --- | --- | --- |
| normal | 正常、正常状态 | 正常 |
| locked | 锁定、已锁定 | 已锁定 |
| lost | 挂失、已挂失 | 已挂失 |
| frozen | 冻结、已冻结 | 已冻结 |

建议编排层允许标准英文值的大小写及首尾空白归一化，例如 ` LOST ` → `lost`。未知表述保留为非法值或进入澄清，不删除后回落为全部查询。“停用”“异常”“不可用”不纳入别名。

“全部”“所有状态”“取消筛选”明确表示不筛选，由编排层转换为不传 status；工具 `list_cards("全部")` 仍返回 INVALID_ARGUMENT。

### 缺省与非法输入

- 缺少 status 或显式 `None`：沿用契约，查询全部。
- 显式空字符串、纯空白字符串、未知枚举、数值、布尔值、列表、对象：不得转成查询全部。
- 已识别 card_query 但 status 非法：返回 INVALID_ARGUMENT，不展示卡片清单；提示可用状态，不原样回显任意非法输入。
- 模糊自然语言：进入澄清，不查询全部作为替代结果；沿用既有最多两轮澄清后转人工规则。
- 一个请求同时要求多个状态，例如“锁定和挂失”：当前 status 只支持单值，追问选择一种状态或全部，不擅自取其中一种、不扩展工具契约。
- frozen 即使当前演示数据无匹配卡，也属于合法状态，返回成功空结果。

## 数据和回执规则

保留 `data={items, total_count}`，每项仅含 card_id、card_no_mask、type、status、credit_limit、single_limit、daily_limit。额度为整数分；储蓄卡 credit_limit 为 `None`，不能改成零。沿用现有按 card_id 排序的结果，不依赖模型重新排列或计算。

- `data.total_count == len(data.items)`；facts 中的数量与结果条数一致。
- 每张卡仅属于当前用户；切换用户后重新查询，不复用前一用户的结果。
- card_no_mask 与数据库保存值完全一致，不拼接、不补全、不猜测完整卡号；回执照抄 facts 中的脱敏值。
- 所有可见数字来自工具事实包，金额展示沿用既有额度格式化逻辑，不由模型计算。
- 交互列表每张卡一行，按“卡号、状态、余额”三列展示；卡类型和信用卡授信额度移入详情。CLI 等无交互入口保留脱敏文本回执，不直接输出余额或完整卡号，并提示使用交互界面查看。

| 查询结果 | 预期回执结构 |
| --- | --- |
| 全部查询且有卡 | “您名下共有 {total_count} 张卡：”后接卡片列表 |
| 状态查询且有卡 | “您名下有 {total_count} 张{状态}的卡：”后接匹配列表 |
| 全部查询且无卡 | 明确说明名下没有卡片，不显示空列表标题 |
| 状态查询且无匹配 | “您名下没有{状态}的卡。”不暗示用户完全没有卡 |
| 参数非法 | 明确说明状态不合法及可选状态，不出现成功清单 |
| 工具执行失败 | 沿用错误回执，不伪装成零张卡，不编造卡片或额度 |

模型润色引入事实包外数字时，沿用数字校验、重试和模板降级，保留 HALLUCINATION_BLOCKED 记录。每次请求记录 trace_id 和审计；成功查询记录 L0 与 list_cards，参数失败记录失败结果，澄清记录未执行工具。

## 连续追问建议扩展项

若本轮确认纳入，应明确验收下面的行为；无需全局开放所有业务的历史继承。

- 同一用户、同一会话，上一轮成功完成卡片查询后，“只看挂失的”可省略“卡片”，但本轮仍重新调用工具，不从旧回复计算结果。
- “再看锁定的”替换状态；“查看全部”清除状态，不累计条件。
- 上一轮为其他业务、查询失败或存在未完成确认流程时，不自动继承卡片查询。现有确认和 OTP 在途流程优先级保持不变。
- 会话重置、用户切换或切换到其他业务后，清除卡片查询上下文，避免跨用户和跨业务继承。
- 没有可用卡片上下文时，孤立的“只看挂失的”应澄清查询对象；明确说“只看挂失的卡”仍可独立执行。
- 历史信息作为数据传入，不写入 system prompt；不得将历史文本当权限或事实依据。

本项涉及共享编排和交互入口，实施前应与本周集成人员约定范围。现有 Web 入口不传查询历史，不能仅靠分类器模拟返回正确意图就声明此项通过。
