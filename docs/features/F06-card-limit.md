# F06 · 调整额度

## 已批准的前端流程（2026-10-10）

自然语言请求或我的银行卡的「调整额度」入口 → 选择固定授信、临时授信、单日交易限额 → 已绑定银行卡列表 → 用户填写调整后的总额度（元） → 核对申请 → 模拟短信验证码 → 手动确认提交。

聊天提到「额度、限额、提额、降额、调额、增额、减额、授信」即可打开额度页面，包括「我的额度是多少」等咨询；明确查询记录、历史、进度或结果时进入记录页。打开页面不提交申请，仍须手动核对和验证码确认。

我的银行卡包含「银行卡」「额度调整记录」两个页签。聊天「查看额度调整记录」及结果中的「查看申请记录」可以直达记录页签。记录持久化保存，可按卡片、类型、审核状态、日期范围筛选并展开详情；重置聊天不会删除记录。

### 实现口径

- 提交与生效区分；审核中/拒绝不改变额度。未提交草稿不保存为申请。
- 固定授信按信用账户共享；提高授信只改变可用授信，不增加余额或生成资金流水。
- 临时额度填写总额度及 1–90 天的期限；生效后开始计时，到期恢复固定额度。普通余额、银行卡查询及 F06 查询会事务刷新到期状态并写系统审计，无需用户手动查看历史才失效。
- 模拟申请上限由 data/card_limit_seed.py 提供；非本人、未绑定、非正常卡/账户、非信用卡授信申请、非法金额/期限被拒；降固定额度不能低于已用/占用额度。
- 单日限额在模拟允许范围内通过；对关联账户共享限额。现有转账按用户累计支出口径取平台硬上限与所设日限额的较小值，预览与执行均检查，不能通过调高额度突破平台上限。
- 预览五分钟有效；确认前重新核对卡状态、账户及额度；验证码失败限流、用户/会话绑定、并发重复提交幂等；申请/额度更新/审计在同一事务内。
- 本次增加 F06 界面私有扩展模型和 agent_* 增量表，未修改冻结 T12/ToolResult 签名或核心 schema.sql；现有 F04 转账/订阅流程保留。

### 演示步骤

1. 进入我的银行卡，用卡号和公开 PIN 逐张验证、确认绑定。
2. 对三张卡分别选择固定授信额度，申请调整到 30,000 元，核对后用模拟验证码确认提交。
3. 打开额度调整记录，默认全部状态，同屏看到审核中、已通过并生效、未通过。
4. 对 2222 卡另行申请高于当前授信的临时额度，展示期限与生效结果；对储蓄卡调整单日限额，随后验证超限转账被拒。
