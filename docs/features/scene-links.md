# 聊天自然追问与场景联动

## 已接通的链路

| 入口 | 后续追问或操作 | 行为 |
| --- | --- | --- |
| 月份账单 | 卡片信息、其他卡、哪张卡花得最多 | 沿用月份展示已绑定卡的关联账户汇总，选择卡后展示该账户流水及卡详情 |
| 账单或流水 | 九月呢、只看收入、只看支出、餐饮呢、主要花在哪 | 继承当前范围，明确月份优先；可按方向、分类、商户筛选 |
| 流水列表 | 第一笔、这笔是什么、同一家商户、退款、重复扣款 | 从当前候选定位详情；查询商户历史、退款标记及疑似重复支出 |
| 订阅列表 | 第一个、每个月一共多少、有哪些快续费、取消它 | 展示周期费用、月均费用及扣款日期；取消进入原有确认流程 |
| 收款人列表 | 第一个、给他转50元 | 定位收款人并生成转账确认草稿 |
| 待确认转账 | 改成100元、修改收款人、取消刚才那个 | 撤销旧凭证后重新预览；原确认不能再执行 |
| 已办理转账 | 成功了吗、照上次再转、再试一次 | 展示真实回执；重复办理生成新草稿，重试不直接执行 |
| 卡片详情 | 最近交易、锁卡、找到了、挂失补卡、额度 | 延续当前卡片并打开已有内联表单，执行仍需原有校验 |
| 理财或持仓 | 第一个、什么时候到期、我买过吗、风险匹配吗 | 查看实际产品与持仓信息；赎回金额不明确时追问，再进入原有预检 |
| 任意查询 | 返回刚才的列表、重新来 | 恢复查询范围或清理当前上下文；不撤销已经执行的业务 |

## 数据和办理边界

- 交易数据只有账户标识，没有直接银行卡标识。因此页面明确使用“关联账户”口径；多张卡共用账户时只汇总一次，不冒称每张卡的消费归属。
- 同账户、同日、同商户、同金额只标记为疑似重复；退款只检索明确退款标记，不能确认与原消费的关联，也不受理真实退款。
- 大额查询按金额绝对值排序；没有风险判定含义。流水明细最多展示50笔，汇总覆盖实际查询范围。
- 订阅近期列表按下次扣款日期排序；月均费用按现有月付、年付数据换算。
- 待复核申请不能通过修改、取消草稿或重来绕过；需先走原有撤销入口。
- 挂失补卡进度来自已有申请记录，不模拟真实制卡、寄送或物流。半额赎回等缺少确定金额的请求先追问，不猜测可赎回金额。
- 上下文按登录用户和会话隔离，有效期30分钟，最多保留256个会话；只记忆安全选择字段，不保存验证码、完整卡号或交易备注。
- 私有组合读工具复用所有权校验、事实包数字校验和审计；冻结的公开接口签名保持不变。模型不可用时可使用确定性追问规则。

## 验证入口

运行 `scripts/verify.sh` 执行完整离线验收。新增 `tests/test_scene_*.py` 覆盖语言规则、事实汇总、跨用户隔离、日期覆盖、卡片点击审计、草稿失效、复核保护及 Streamlit 联动；`tests/test_reply_animation.py` 验证逐字显示及不重放。
