【任务卡 #20】收款人自助添加（聊天触发 → 表单 → 落库 → 可转账）

第一步：读 `CLAUDE.md` 和 `docs/01-接口规格.md`，用 5 行复述你理解的约束，等我确认再动手。

范围：只允许改下列文件，其他一律不动。
- `docs/01-接口规格.md`（**人类已批的 SPEC-CHANGE**：见下「接口」三条）
- `data/dao.py`（加 `insert_payee` DAO 原语）
- `tools/payee.py`（**新文件**，放 `add_payee`；不要塞进 `tools/transfer.py`，避免 300 行越界）
- `agent/classifier.py`（加 `payee_add` 意图 + 触发词）
- `agent/orchestrator.py`（识别 `payee_add` → 返回信号；**提供表单提交入口**；若逼近 300 行按既有方式拆）
- `interfaces/web/app.py`、`interfaces/web/components.py`（表单组件 + 渲染）
- `tests/`（新增单测 + 界面/分层守卫）

接口：人类已批的契约变更，**逐字照此实现，不得自行改名/加字段**：
1. 新工具 **T17 `add_payee(name: str, phone: str) -> ToolResult`**
   - `data` = `{payee_id, name, masked_phone}`；错误码复用既有枚举（`INVALID_ARGUMENT` / `FORBIDDEN` / `TOO_MANY_ROWS`）
   - 归属：只写当前 user（`set_current_user` 口径），越权 → `FORBIDDEN`
2. 新意图 **`payee_add`** 进 §3 意图清单（槽位：`name` 可选、`phone` 可选）
3. §5 档位：**`payee_add` → L1**，且**不发确认卡、不要 OTP**（表单提交本身即用户确认；理由：只加联系人、不动钱）

要求：
1. **手机号必填**。落库前按铁律 8 **脱敏**为 `138****0001` 形式（保留前 3 + 后 4，中间 `****`）。
   入参校验：非空；11 位数字，或已是脱敏形式。**完整手机号绝不落库、不回显、不进日志/审计**。
2. **不收卡号**（本卡明确不含卡号字段）。新收款人 `is_whitelist=0` → 之后转账走 **L2 + OTP**（既有口径，别改）。
3. **聊天触发**：用户说「加收款人 / 添加收款人 / 新增收款人 / 加个联系人」→ 编排层识别为 `payee_add`
   并让界面**弹表单**。**不要**只回一句文字让用户干等。
   ★ 实现要点：**界面靠 `turn.intent == "payee_add"` 判断是否出表单** ——
   **不要**给 `Turn` 或 `POST /api/chat` 的响应加第 7 个字段（那 6 个字段是钉死的契约）。
4. **界面表单**：`components.payee_form()` = `st.form`（姓名 + 手机号 两个输入 + 提交按钮）。
   提交后**经 `agent/` 层**落库（**不得** `interfaces/` 直连 `tools/`），回执显示
   「已添加 <姓名>（138****0001）」+ 提示「现在可以给他转账了」。
5. **可转账**：添加成功后，「给张三转 100 元」与「给 138****0001 转 100 元」都应命中
   （`find_payee` 已按 姓名/手机号 子串匹配，别改匹配口径）。
6. **去重**：同一 user 下同名同手机号重复提交 → 不重复插入（返回既有收款人并说明），
   或明确允许重复并说明理由 —— 二选一，写进交付说明。

禁止：
- 在界面里写业务逻辑（一律调 `agent/`）
- 完整手机号出现在任何回执 / 日志 / 审计 / `data` 字段里
- 改动 `tools/transfer.py` 现有转账逻辑、改动其它已 PASS 卡的测试
- 新增依赖（铁律 6）

交付：按模板 + 界面截图三张（① 聊天里说「加个收款人」弹出表单 ② 填完提交的回执
③ 用新收款人成功走到 L2 确认卡）。
