## 顺序依据

- **风险测评必须在理财之前** —— 没测评就申购，系统回 `INVALID_STATE`（实测）。
- **写路径要先泛化** —— 确认卡 + OTP 现在是转账专用，10 个写功能都依赖它；W1 先做（落在「订阅取消」上）。
- **卡片查询先于卡片操作**；**收款人先于 AA / 送礼**。
- **同一周只碰一个域** —— `classifier.py` / `read_routes.py` / `templates.py` 是共享文件，多人同改必冲突。

## 每周节奏

- 周一：开工本周「重」的那一项，定好共享文件本周归谁改
- 周三 / 周四：出一版能过 `verify` 的
- **周日收束**：`uv run pytest -q` + `bash scripts/verify.sh`（**必须 6/6**）→ 更新 `board/ledger.md` → 定下周范围
