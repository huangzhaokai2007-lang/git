## 前置条件与交接

- **W1 先打基础：**莫的 F04（订阅取消）要形成可复用的写操作确认流程，供汤的后续卡片操作、黄的转账和莫的理财交易使用。F04 的旧 card-24 有开工记录，莫先核对现有分支与实施者，避免重复开发。
- **W1 联系人与卡片入口：**黄先验 F17（解析）再验 F22（新增）；汤先验 F01（查询）再验 F05（申请）；舒从 F23（余额）和 F02（流水）建立后续金额回归口径。
- **W1 定义两项缺口：**黄在 10-04 前提交 F16 的预约触发、时区、持久化和取消方案；莫在 10-04 前提交 F18 的提醒触发、渠道、去重与取消方案。需要新增工具、字段或依赖时，队长先确认契约。
- **W2 遵守顺序：**汤先调额/锁卡，再为 W3 的解锁/挂失准备状态；黄在 F17/F22 基础上验 F21（单笔）与 F15（AA）；莫先做 F10（测评）再联调 F11（推荐）；舒核对 F14（账单分析）与 F02 的数据口径。
- **W3 高风险联调：**汤验 F08/F09 的 L3 延迟与撤销；黄完成真正的 F16 预约执行，不能把即时转账改名；莫验 F12/F13，确保风险测评、持仓、确认和幂等闭环；舒验 F03/F24，并协助检查金额与审计一致性。
- **W4 收口：**黄完成 F20（送礼）；莫完成 F18（提醒）。汤、舒分别复测卡片与账户/账单全链路，四人共同跑跨板块演示与回归；新功能延期要在周总结中注明，不挪走他人的责任。

## 协作约束与周日门禁

每周共享编排文件由一名集成人员协调：W1 莫、W2 黄、W3 汤、W4 舒。改 `agent/classifier.py`、`agent/orchestrator.py`、`agent/read_routes.py`、`agent/write_flow.py`、`agent/templates.py` 前先在 PR 说明范围与依赖；板块负责人仍对自己的功能验收负责。

每周日依次完成：本周功能演示与异常场景 → `uv run pytest -q`、`bash scripts/verify.sh` → 审核合并与认领表更新 → [周总结](weekly/README.md)记录证据、阻塞和下周安排。10-25 还需核对 F01–F24 各自的验收 PR，并联调卡片、转账、订阅、理财、账单。仅有原代码或旧测试通过不算本轮完成。

仓库仍使用原五层架构，旧 card-* 任务卡保留作历史资料；各功能的具体验收点见对应 Fxx 页。
