## 开工顺序

- **W1 机制先行：F04** 接通订阅取消，并建立后续卡片、理财等写操作复用的确认流程；已有单笔转账必须回归。F01 提供后续选卡入口。
- **W2 先选卡再操作**：F05–F09 共用 tools/card.py，指定集成人员协调，避免五人同时修改同一段代码。
- **W3 先测评再推荐/申购**：F10 是问卷与评估流程，不算资金写操作；F13 赎回依赖有效持仓和封闭期校验。F14 可独立推进。
- **W4 先验联系人，再联调 AA/预约**：同周先验 F17；F18 提醒在开工前明确形态；F16 要实现真正预约执行，不能把现有即时转账当预约。
- **W5 完成交叉回归**：F20/F21/F22 联调资金与联系人，F23/F24 检查余额及账单一致。F17/F22 原实现可提前复用，不必等到排定周才使用。

## 每周节奏

周一认领功能，登记集成人员和共享文件范围；周三/周四合并第一批可验收改动；周日演示、跑门禁、审核合并并记录总结。负责人、审核人和功能状态只在[认领表](features/README.md)维护。

周日门禁：

```bash
uv run pytest -q
bash scripts/verify.sh
```

必须提供真实输出和本周功能演示，记录通过数与限制。`verify.sh` 六段通过仍不代替新增功能的专门验收。剩余工作顺延时记录原因和新交付日期，不把它算入已完成数量。
