# F06 额度调整实施计划

用户已批准：调整类型 → 已绑定卡选择 → 用户填写目标额度（临时额度含有效期）→ 确认与验证码 → 提交申请；我的银行卡增加额度调整记录页签。

**Goal:** 完成固定授信、临时授信、单日交易限额及持久化记录，三张模拟信用卡分别展示审核中、通过生效、未通过。

**Architecture:** interfaces 只调用 agent；agent 调用新增的私有 F06 工具；工具经增量 DAO 保存预览凭证、申请和临时授信。保留冻结的 T12 签名及核心 DDL，不新增依赖。所有金额用整数分，审批为确定性模拟规则。

**Tech Stack:** Python 3.11、SQLite、Pydantic、Streamlit、pytest。

## 决策与边界

- 信用授信按信用账户共享；三张演示卡各有独立账户，避免干扰现有余额。
- 1111 固定/临时申请为 pending，2222 为 approved，3333 为 rejected；单日限额在允许范围内直接生效。
- 临时额度输入调整后的总额度，期限 1–90 天，到期固定额度不变、可用额度同步扣减；读/提交时刷新到期状态。
- 申请记录保存拒绝和审核中状态，不保存未提交草稿或 OTP；重置聊天不删除记录。
- 新增的是界面私有扩展，不修改 docs/01 的冻结接口或 schema.sql。测试夹具和模拟审批参数是演示数据来源，不由 LLM 生成。
