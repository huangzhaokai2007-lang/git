# 单一聊天主界面：已批准设计与实施计划

用户确认移除聊天、账单图表、审计时间轴、银行卡的四选一页面导航，将能力并入快捷场景。

## 行为

- 唯一主界面为聊天，保留应用名称、账户余额及快捷场景。
- 管卡打开既有动画卡片列表，额度、锁卡、挂失补卡业务记录仍在卡片列表页签中；记录链接改为打开聊天内列表及指定页签。
- 看账单仍经 agent 查询，图表紧随聊天结果。保留从会话回执提取的分类、趋势及拉取近三期的入口，不在 UI 推算业务数字。
- 快捷场景末尾增加操作记录，主内容区展示当前会话用户请求及中文业务反馈，技术审计详情默认折叠。不执行业务、不调用模型，不清空聊天。
- 快捷入口保持正在办理的表单；单纯展开、收起记录不丢失草稿输入。明确重置会话仍按原规则清理会话界面，持久业务记录不删除。
- 不新增依赖、不修改业务权限、数据库或公开工具契约。

## 实施和验收

1. 新增 tests/test_web_single_chat.py，先观察导航仍存在、操作记录入口缺失、账单请求隐藏草稿导致失败。
2. 修改 app.py 单一聊天渲染；新增 activity_ui.py 展示业务记录与折叠审计；scenes.py 增加入口；卡片记录改为聊天内导航。
3. 迁移原页面切换测试为快捷入口间切换，保留绑定、锁卡、额度、动画及用户隔离断言。
4. 修复快捷入口过早 rerun 导致输入清理的问题，以同轮完整渲染或按钮 callback 保留控件状态。
5. 运行相关 UI 测试、全量 pytest 与 scripts/verify.sh；独立审查及浏览器检查，保留截图和日志。
6. 保留当前分支与演示数据库，本地提交，不自动推送。

## 实际验证

- 新增三项单一聊天 UI 回归通过，包括记录展开与收起、账单快捷及三期查询时保留未提交绑卡输入。
- 迁移的五个卡片 UI 测试文件共五十四项通过；保留绑定隔离、额度草稿、遮罩及锁链状态断言。
- 完整验收：1516 passed；评测场景 53/53；红线检查一百项、红队与通道/接口冒烟均通过。
- 独立审查发现三期查询早期 rerun 会清理草稿，已先复现失败再改为按钮 callback，复核通过。
- 浏览器已检查简化侧栏、操作记录入口及默认折叠的技术审计详情；演示继续使用原数据库。
