# 答辩提纲（卡 19 · 演示与问答预案）

> 配套：`uv run python scripts/demo.py`（一条命令跑完三条通道，离线可演）；
> 数字全部来自本仓库实测（测试数、红队结果、余额等），现场可当场复跑。

---

## 0. 一分钟定位（电梯稿）

> 我们做的是一个**能用自然语言办银行业务**的智能体：说「查一下余额」「上个月花了多少」「给王五转 100 元」，
> 它自己判意图、补槽位、**用代码**定权限档、出确认卡、验短信验证码、幂等执行并写审计。
>
> 关键设计只有一句话：**大模型只负责"听懂人话"和"把话说顺"，钱和权限的判定权全部在 Python 代码里** ——
> 金额、余额、限额、状态变更、越权判断、数字校验，一条都不让模型碰。
>
> 三条通道（网页 / HTTP 评测入口 / IM）共用同一个编排层；30 条红队攻击集实测**未得逞 30/30、造成危害 0/30**；
> 全项目 **970 条单测 + 30 条评测用例 + 84 条红线测试**，`bash scripts/verify.sh` 一条命令离线跑完。

## 1. 技术亮点（每条：一句话 → 代码落点 → 现场怎么证明）

### 1.1 分层单向依赖（不越层是硬约束）

一句话：`交互层 → 编排层 → {护栏, 工具层} → 数据层`，反向调用与越层调用都是 bug，且**有机器守卫**。

- 落点：`interfaces/`（网页/评测入口/IM）只 import `agent/`；`agent/` 可调 `guard/`、`tools/`；`tools/` 只调 `data/`。
- 证明：`uv run pytest tests/test_web_layering.py` —— 用 **AST** 扫 `interfaces/**`：不得 import `tools`/`data`/`guard`、
  不得出现 SQL 语句字符串、不得"借命名空间"掏护栏层（`x.injection.y`）。
- 加分点：IM 通道的包裹入口是 `agent/channel.py` 的薄函数（`interfaces → agent → guard` 单向链）。

### 1.2 四步写路径（任何"直接执行"的分支都是 bug）

一句话：`preview_*（只算不执行）→ 权限档（代码判定）→ 用户确认（必要时 OTP）→ 幂等执行`。

- 落点：`agent/write_flow.py`（写路径唯一归属）+ `tools/transfer.py`（`preview_token` TTL 300s、参数绑定、幂等）。
- 证明：现场跑 `uv run python scripts/demo.py` 的第 ⑤ 段：确认卡（L2、`executed=false`）→ 验证码 → `executed=true`、余额 46,634.00 → 46,534.00。
- 加分点：重复调用同一个 token 返回同一结果（幂等），不会重复扣款。

### 1.3 护栏与权限分级 L0–L3（LLM 无权干预）

一句话：档位与降级因子由 `guard/permission.py` 纯代码判定，命中 ≥2 个降级因子 → 转人工。

- 档位：L0 只读 / L1 白名单且 ≤500 元（会话内确认）/ L2 新收款人或 >500 元等（确认 + OTP）/ L3 挂失·解锁·大额（双因子 + 延迟 60s 可撤销 + 人工复核）。
- 降级因子：`night / velocity / amount_jump / device_change / geo_change`。
- 硬约束：单笔 ≤500 元、单日累计 ≤2,000 元，超限直接 `OVER_LIMIT`（不落库）。
- 证明：现场转 600 元 → 档位升到 L2 且要求 OTP；转 600 元以外的越权/超限请求 → 被工具层拒。

### 1.4 注入攻防（三层防线 + 30 条攻击集）

一句话：规则层**先于模型**拦（命中即拒答、**零 LLM 调用**），工具层兜归属与限额，交互层用确认卡复述意图。

- 落点：`guard/injection.py`（10 条规则 + 归一化解混淆：unicode/百分号/全角/零宽）+ `agent/channel.py`（不可信文本包裹 `<untrusted_data source="…">`）+ `tools/_query_common.require_owned`（越权 → `FORBIDDEN`）。
- 实测（`uv run python scripts/redteam.py`，威胁模型 = **分类器被完全劫持**）：5 类 × 6 条 = 30 条，
  **未得逞 30/30（100%）**、**造成危害 0/30**、规则层确定性硬拦 22/30；未命中的 8 条由下游兜住（写路径要确认、读路径按会话圈定、单笔上限）。
- 答"为什么还有 8 条没硬拦"：那正是纵深防御的价值 —— 关键词表不可能穷尽措辞，所以关键不变量不押在措辞上。

### 1.5 数字校验（幻觉的物理隔离）

一句话：回执**先由模板从事实包渲染**，LLM 只能润色措辞，润色结果里出现 facts 之外的数字 → 重生成一次 → 仍不过 → 降级模板 + `HALLUCINATION_BLOCKED` 审计。

- 落点：`tools/schemas.ToolResult.facts`（唯一数字来源）+ `guard/facts_check.verify_numbers` + `agent/templates.py`。
- 证明：`uv run pytest tests/test_facts_check.py`；现场可故意问一个模型"想说"的数字，看回执仍只有库里的数。

## 3. Q&A 预案

### 3.1 为什么自建核心？不用 LangChain / 编排框架？

- 30 秒答：银行场景要的是**可审计、可复现**，不是"聪明的编排"。框架把控制流藏在配置里，我们的状态机
  （`IDLE→CLASSIFY→SLOT_FILL→PRECHECK→…→AUDIT`）是显式代码，**每一步都能被单测钉住**，也便于写审计与做权限判定。
- 补一句：依赖只有 `pydantic / fastapi / uvicorn / streamlit / openai / python-dotenv / pyyaml`（铁律 6：不引新框架）。
- 证据：`agent/orchestrator.py` 的 `STATES` 与 `Turn.states`（回执里带到达过的状态序列，测试断言"不可跳步"）。

### 3.2 LLM 的权限边界在哪？

- 30 秒答：模型只有两件事 —— **意图分类**（输出 `intent/confidence/slots`）和**措辞润色**（不得改动数字）。
  它不能决定金额、余额、限额、权限档、是否执行、能不能转账；这些全部由代码判定，且数字必须能在**事实包**里找到。
- 证据：`agent/classifier.py`（只出结构化 JSON，不判权限）+ `guard/permission.py` + `guard/facts_check.py`。

### 3.3 幻觉怎么防？

- 30 秒答：三条 —— ① 回执用模板、数字从 `facts` 注入；② 润色结果过**数字校验器**，出现 facts 之外的数字就降级模板；
  ③ 每条越界都写 `audit_log(HALLUCINATION_BLOCKED)`，可追溯。
- 追问"模型编日期/编结论呢？"：日期不参与数字校验但需能在 facts 里找到同形串；越界即降级，D 级兜底是**模板原文**，不是模型文本。

### 3.4 越权怎么防？

- 30 秒答：工具层白名单 + **归属断言**（所有资源 id 必须属于当前会话用户，否则 `FORBIDDEN`）+ 读路径按会话圈定 +
  写路径必须过确认卡/OTP + 单笔与单日限额。
- 现场证据：红队「越权操作」类 6 条 —— 硬拦 4、兜住 2、**危害 0**；红队脚本会在合成库里另插入"他人账户"作探针
  （999,900.00 元），实测它从未出现在任何回执里。

### 3.5 和真实银行是什么关系？（合规）

- 30 秒答：**没有任何关系**。全部是模拟环境 + 程序生成的合成数据，不连接任何真实银行、不调用真实账户、
  不做真实资金操作；展示的手机号/卡号一律脱敏；理财推荐由本地规则与合成产品库给出，**不构成投资建议**。
- 证据：README §13 合规声明；`.env` 里只有演示用 LLM key，**不含任何真实金融凭证**。

### 3.6 其他高频追问（各 20 秒）

| 问题 | 答法 |
| --- | --- |
| 分类器被完全劫持会怎样？ | 红队就是按这个最坏情况跑的（stub 直接给出攻击者想要的意图）：30 条里 22 条被规则层硬拦，剩下 8 条被确认卡/归属/限额兜住，**危害 0/30** |
| 多用户怎么做？ | demo 是单用户 + 会话隔离（`set_current_user` 注入）；IM 通道按 `chat_id` 分会话。要做真多租户，缺的是"IM/网页身份 ↔ 银行用户"绑定，接口已留出 |
| OTP 为什么固定 6 位？ | 规格 §5 的 demo 口径；**值只存在于工具层**（`tools/transfer.py`），界面与 IM 通道都不知道它，演示时由讲解人念出（铁律 2/3） |
| 为什么用 SQLite？ | 单机演示要"零外部依赖、离线可跑"；写了线程安全连接（每线程一份 + `BEGIN IMMEDIATE`）与结构漂移自检，未来换 PostgreSQL 只动 `data/` |
| 怎么保证不回归？ | 970 单测 + 30 用例 + 84 红线 + 6 段一键验收；关键修复都配**变异自检**（把修复改回去，测试必须变红） |
| 延迟与成本？ | 只读请求 1 次模型调用（意图分类）+ 1 次润色；命中注入规则时 **0 次**模型调用；分类结果温度 0 以便复现 |
| 没网怎么办？ | 三条：① 工具层零外网（业务数字全来自本地库）；② 模型不可用自动降级为追问/未接通；③ `scripts/demo.py` 与 `verify.sh` 全程离线 |
| 为什么不用真实攻击流量测？ | 这是合成环境 + 合成攻击集（自建 30 条、5 类）；真实渗透要在真实系统与授权下做，不在本项目范围 |
| 最难的一处 bug？ | 分类器在温度 0 下也会返回英文 `period="last_month"`，旧代码认不出就静默用"本月"→「上个月花了多少」答成 0.00 元。修法：别名表 + 认不出一律追问（卡 17b），并补了真机回归用例 |

## 4. 现场故障预案

| 状况 | 兜底 |
| --- | --- |
| 端口被占 | `API_PORT=8010 uv run python -m interfaces.api`（IM/Streamlit 同理） |
| 没网 / 模型限流 | 用 `uv run python scripts/demo.py`；或直接讲已跑通的输出（`board/` 下有历史验收记录） |
