> 目标：**15 分钟讲完所有已实现能力**，每个动作用一句话触发，卡面即证据。

## 0. 开场准备（60 秒）

```bash
cd repo-whitelist
rm var/bank.db && uv run python -m data.seed --reset      # 重置演示库（合成数据）
uv run streamlit run interfaces/web/app.py --server.port 8501   # http://127.0.0.1:8501
```

**开场三句话**：
1. 五层架构：`interfaces → agent → guard/tools → data`，LLM 只做「听懂」和「措辞」；
2. 所有金额/余额/档位来自工具层的事实包，卡面上的每个数字都能回溯（有数字校验器守着）；
3. 所有写操作都是 `预览 → 定档 → 确认（必要时验证码）→ 幂等执行`。

## 1. 剧本五幕

### 幕 1 · 收款人域（≈3 分钟）「先看家底」

| 动作（照着说） | 预期 | 讲什么 |
|---|---|---|
| `我的收款人有哪些` | 表格 + 顶部统计（共 5 人 · 白名单 2 · 黑名单 0 · 已过期 0）+ 筛选（全部/白名单/黑名单/已过期白名单）+ 每人一行：姓名·手机·类型·标签·有效期·额度与剩余·备注·卡号·最近转账 | 一张卡 = 规格里的「查询收款人卡片」，筛选切白/黑名单，**不另做功能** |
| 点某人的「加白」 | 白名单确认卡（含额度/有效期输入位） | 白名单要设**额度 + 有效期** |
| `给王五加上标签：房东` / `给张小美加个备注：妈妈，别转错` | 各自的 L1 确认卡 → 确认即生效 | 标签能**指代人员**（"给房东转300"），备注只是给人看 |

### 幕 2 · 解析关卡（≈2 分钟）「同名怎么办」

| 动作 | 预期 | 讲什么 |
|---|---|---|
| `给李四转 100 元` | 追问「找到 2 个同名…」**并同时弹出解析卡**（两个李四，带脱敏手机号） | 解析有**五层优先级**：标签 → 姓名 → 拼音 → 子串 → 会话记忆 |
| 点解析卡里第二位 | 直接出**这个**李四的确认卡（不再二次追问） | 点选即锁定 id；卡 5 分钟不选自动作废 |
| `给房东转 100 元` | 直接用**标签**命中王五 | 标签=人的别名 |
| `给wangwu转 100 元` | 拼音也能命中王五 | 多音字/拼音都支持（单→shàn 也能匹配） |

### 幕 3 · 风控关卡（≈4 分钟）「谁能免码、谁必须码」

> ⚠️ **先看时间**：白天（06:00–23:00）按下面正常演；深夜（23:00–06:00）非白名单会直接 **L3 待人工复核**——
> 这也是特性（风险升级），脚本第 5 节有话术。

| 动作 | 预期 | 讲什么 |
|---|---|---|
| `给王五转 100 元` | 完 **L1 免验证码**，卡面「白名单专属额度内，深夜时段也免验证码」 | 白名单 = **额度内 + 有效期内** 免码 |
| `给张小美转 100 元` | **L2 要验证码** | 非白名单一律要码 |
| 把金额改成 `600 元` | 拒绝：「超过单笔上限 500.00 元」 | 超限 → 按普通处理（要码/拒绝） |
| `把王五的白名单有效期改到 2026-10-01` → 再 `给王五转 100 元` | 确认卡变 **L2**，提示「白名单已过期，按普通收款人处理，需要验证码」 | **到期自动降级** |
| `把王五的白名单有效期改回 2026-12-31` | 恢复 L1 | 改白名单信息本身要**验证码**（L2） |
| `把王五拉黑`（他**在白名单**里） | 卡面：「变更：加入黑名单**并移出白名单**」「影响：…；**白名单专属额度同时失效**」→ 确认即生效 | 三态可自由切换：白名单 ⇄ 普通 ⇄ 黑名单 |
| `把赵六加入黑名单，原因：总是赖账` → `给赵六转 100 元` | 直接拒：「这笔操作不能办理（FORBIDDEN）：赵六 已在黑名单，不能转账或送礼。原因：总是赖账。」 | 黑名单**三处拦截**：转账/定时/送礼，都不出卡 |

### 幕 4 · 验证码关卡（≈1 分钟）「码错了怎么办」

| 动作 | 预期 |
|---|---|
| 在 L2 卡上回 `确认` | 「请输入短信验证码以完成这笔…」 |
| 输 `000000` | 「验证码不正确，请重试（还可试 N 次）」——**不重开流程** |
| 输 `123456` | 执行成功回执（带流水号/时间/金额/收款人） |

讲：固定码 123456、无 60 秒冷却、3 次错误锁定本次操作并可返回修改；通过后**回到原操作继续**。

### 幕 5 · 三条业务流（≈5 分钟）

**A. 定时转账（含循环与提醒）**
| 动作 | 预期 |
|---|---|
| `2026-10-31 09:00 给房东转 300 元` | 定时确认卡（预约时间 + 执行说明「到点才扣款」）→ 确认 → 预约成功（**不扣款**） |
| `每个月月末给房东转 300 元，到年底` | 卡面「循环：每月循环（…月末自动对齐），循环至 2026-12-31」；首期自动算到最近月末 |
| `我的预约有哪些` | 表格（时间/收款人/金额/状态⏳待执行）+ **预约卡**（立即执行 / 改时间 / 取消 / 改金额收款人） |
| `把那笔预约改成 200 元` | 卡面「金额 100.00 元 → 200.00 元」→ 生效（档位保持冻结值） |
| 把执行时间改到 **6 小时后**，再说任意一句（如 `查一下余额`） | 回执前面带「【执行前提醒】…将向 X 转账 Y 元；想改或取消可以说…」 | 

**B. AA 收款（全员白名单 vs 含非白名单）**
| 动作 | 预期 |
|---|---|
| `向王五和李四 AA 收款 200 元` | **L1 免码**（两人都是有效白名单），卡面「每人 100.00 元（一键均摊）」 |
| `向王五和赵六 AA 收款 300 元` | **L2 要码**，卡面多一行「验证码原因：含非白名单收款人：赵六」 |
| `AA 收款，王五 100 元、赵六 200 元` | 按人金额，合计校验（不符会拒） |
| `我的 AA` | 表格（事由/合计/已付 N/M 人/状态/截止）+ **AA 卡**（登记已付 / 撤销） |
| `提醒赵六付款` | L1 卡 → 「已提醒赵六支付 150.00 元（demo 期为模拟提醒，仅留痕）」 |

**C. 送礼（5 状态 + 幂等）**
| 动作 | 预期 |
|---|---|
| `我想 2026-10-30 在京东给王五买一瓶 399 的香水，送到上海市某某路 1 号，订单号 JD001` | 送礼卡（平台/地址/订单号/清单/合计/可用余额 vs 账户余额）→ 确认 → 123456 → **订单号 ord_…** |
| 同订单号再说一次 | 「该订单已存在送礼计划（订单号 JD001），不能重复下单」→ **幂等** |
| `我的送礼订单` | 表格（订单号/收货人/送达日期/金额/状态🧾待支付）+ **送礼卡**（支付/取消） |
| `把这单礼物支付了` → `这单礼物发了` → `这单完成了` | 依次 已支付 → 已发货 → 已完成（发货/完成 **不动钱**，L1 免码） |
| 对「已发货」的单说 `取消那个礼物订单` | 拒绝：「没有可取消的订单（未发货才能取消）；当前：王五（已发货）」 |

## 2. 三条横向关卡（这是评分点，值得单独讲 30 秒）

| 关卡 | 一句话 | 实现 |
|---|---|---|
| **解析关卡** | 「你说的人是谁」 | `agent/payee_resolve.py`：标签/姓名/拼音（含多音字）/子串/会话记忆；多命中 → 解析卡 |
| **风控关卡** | 「这笔要不要验证码」 | `agent/payee_risk.py`：黑名单拒 → 白名单额度内且未过期 → 免码；否则按普通（要码）；超限升档 |
| **验证码关卡** | 「确认是你本人」 | `agent/write_flow.py`：一个 OTP 状态机，所有写操作共用；通过后**回到原卡片**继续 |

| 项 | 值 |
|---|---|
| 单笔转账上限 | **500.00 元** |
| 当日转账上限 | **2,000.00 元** |
| 白名单专属额度 | 王五/李四各 **1,000.00 元/月**（可改） |
| 白名单有效期 | 王五 2026-12-31 · 李四 2026-11-15（可改，过期即降级） |
| 夜间时段 | **23:00 – 06:00**（夜间是降级因子） |
| 验证码 | **123456**，无冷却，3 次错误锁定 |
| 预约时间 | 必须 **> 5 分钟**、**< 1 年**、且是**将来** |

## 4. 防翻车清单

| 风险 | 现象 | 应对 |
|---|---|---|
| **深夜演示**（23:00–06:00） | 非白名单转账直接 **L3 待人工复核**（night + 首次） | ① 白天演示；② 或改用它讲「风险升级 → 人工复核」，再回 `撤销 pend_xxx` |
| 演示时间写成过去 | 被拒「已经过去了」 | 用 `2026-10-30` 这类将来日期，或说「明天」「下周一」「月底」 |
| 金额 > 500 | 被拒「超过单笔上限」 | 用 100/200/300 |
| 给黑名单的人送礼 | 直接拒（设计如此） | 先 `把赵六移出黑名单`（要验证码） |
| AA 全是白名单却要码 | 不会：全有效白名单 → L1 | 若被要码，检查某人白名单是否**过期** |
| 解析卡点了没反应 | 超过 5 分钟已作废 | 重新说一句 `给李四转 100 元` |
| **连续快速演示多笔转账** | 触发 velocity（10 分钟内 ≥3 笔写操作）→ 升 L3 待人工复核 | 每笔之间停一下，或演示前重置库；也可主动讲「短时高频会升级人工复核」 |
| 同一平台订单号下两次单 | 第二次被拒「该订单已存在送礼计划」 | 这是**幂等**演示点，换个订单号继续 |
| L3 之后又回「确认」 | 提示「已在待人工复核（同一笔不会重复登记）」+ 同一编号 | 正好演「不会重复登记」 |
| 白名单额度内转账应免码 | 若卡片显示 L1 → 点确认应**直接成功** | 若报「验证码不正确」，强刷页面（旧前端） |
| 送礼预算 5000 | 只配 498 元的礼物（目录上限） | 讲解「预算内自动选品，目录就这些」 |

## 6. 常见提问与标准答法

| 提问 | 答法 |
|---|---|
| 「金额是 LLM 算的吗？」 | 不是。LLM 只输出意图与槽位；金额/余额/额度/档位全部来自工具层事实包，卡面数字有校验器守着（出现事实包外的数字就降级为纯文本回执） |
| 「为什么要验证码？」 | 规格 §5 的档位表：非白名单 / 超额度 / 超限 / 白名单过期 → L2；L3 转人工复核 |
| 「白名单过期怎么处理？」 | 自动降级为普通收款人（`payee_risk.is_expired`），卡面提示「白名单已过期，按普通收款人处理」 |
| 「能改预约/订单吗？」 | 预约可改**时间/金额/收款人**（改后重走解析与风控）；订单可支付/取消（未发货可退）/发货/完成 |
| 「定时是怎么跑的？」 | 惰性结算：每次交互先结算到期项（无后台进程，一次性 CLI 也能用）；到期前 24h 有**执行前提醒** |
| 「怎么保证不重复扣款？」 | 预览凭证 CAS + 条件更新抢锁 + 幂等键（送礼平台订单号唯一） |
| 「接口能随便改吗？」 | 工具签名与返回字段是冻结契约，扩展只能**新增工具**（本域已新增 T28–T51），改既有签名需走 SPEC-CHANGE |
