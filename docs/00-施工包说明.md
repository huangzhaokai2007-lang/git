# 00 · 施工包说明（先读这一页）

这个目录就是你们的仓库根。**代码由 AI 写，你们负责规格、验收和演示。**
不要自己动手写业务代码，也不要让 AI 自己发挥设计——顺序错了必翻车。

## 文件清单

| 文件 | 作用 | 谁能改 |
|---|---|---|
| `CLAUDE.md` | **AI 的项目宪法**：铁律、架构、命令、交付要求。Claude Code 每次会话自动加载 | 只有队长改，改动要全员知会 |
| `docs/01-接口规格.md` | **唯一接口来源**：DDL、15 个工具契约、意图清单、状态机、权限矩阵、用例格式 | **只有人改**，改完要在 commit 里标 `SPEC-CHANGE` |
| `docs/02-AI指令剧本.md` | **19 张任务卡**，每张可直接复制给 AI，含验收命令与"你该做什么" | 自由 |
| `scripts/verify.sh` | 一键验收：单测 → 用例 → 冒烟对话 → 红线检查 | 自由 |
| `.claude/commands/` | 自定义斜杠命令：`/verify` `/redteam` `/newscene` | 自由 |
| `pyproject.toml` | 依赖（uv 管理，Python 3.11） | 加依赖前问队长 |
| `.env.example` | 环境变量样板，复制成 `.env` 填 DeepSeek key | `.env` 不进 git |

## 第一天照做（约 40 分钟）

```bash
# 1. 进目录、装依赖
cd ai-banking-agent
uv sync

# 2. 配置模型（用 DeepSeek，OpenAI 兼容接口，国内可直连）
cp .env.example .env
#   打开 .env 填 LLM_API_KEY=sk-xxxx

# 3. 确认验收脚本可运行（现在还全是 SKIP，正常）
bash scripts/verify.sh

# 4. 建仓
git init && git add -A && git commit -m "card-00: 骨架与施工包"
```

## 然后怎么干活

```bash
claude                      # 在仓库根目录启动 Claude Code
# 第一句先粘贴 docs/02 第 0 节的"万能指令模板"或者直接贴【任务卡 #00】
```

节奏：一天 1–2 张卡 → 每张卡跑一次 `bash scripts/verify.sh` → 过了就 commit → 下一张。
卡 10（确认卡 + OTP 的写入闭环）是第一个真正的里程碑，计划落在第 2 周末。

## 三条最重要的提醒

1. **AI 说"完成"不算完成。** 没有 `verify.sh` 的真实输出，一律当没做。
2. **接口只能人改。** 一旦 AI 悄悄改了字段名，三天后你会在一堆不一致里崩溃。
3. **上下文超过 70% 就 `/compact` 或开新会话。** 长会话后期 AI 会开始瞎编。

## 分工建议（与备赛方案一致）

P1 队长：维护 `CLAUDE.md` 与规格、跑验收、写演示剧本的"业务判断"部分、答辩
P2 后端：卡 01–07（数据层 + 工具层），最容易外包给 AI 的部分
P3 AI/安全：卡 08–15（编排层 + 护栏），**卡 12–15 是评分主战场，本人必须读懂每一行**
P4 前端：卡 16–17（界面 + IM 通道）+ 录屏

卡 18–19（交付物与演示材料）四个人一起，P1 主导。
