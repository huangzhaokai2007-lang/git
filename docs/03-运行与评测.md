# 03 · 运行、部署与评测入口

> 面向"把项目跑起来"和"照契约评测"两件事。总览与架构见仓库根 `README.md`；
> IM 通道的配置细节见 `interfaces/im/README.md`。本文件不重复接口规格（见 `01-接口规格.md`）。

## 1. 三种起法

### 1.1 本地（推荐给评委现场）

```bash
bash scripts/bootstrap.sh          # 一条命令：uv sync → 造合成数据 → 跑一键验收 → 打印下一步
bash scripts/bootstrap.sh --quick  # 只装依赖 + 造数据（跳过验收，约 20 秒）
```

然后按需要起服务（各起一个终端）：

```bash
uv run streamlit run interfaces/web/app.py    # 网页端      http://127.0.0.1:8501
uv run python -m interfaces.api               # 评测入口    http://127.0.0.1:8000/api/chat
uv run python -m interfaces.im                # IM 通道     http://127.0.0.1:8090/im/loopback
```

### 1.2 容器（同一镜像两个服务）

```bash
cp .env.example .env               # 可选：填 LLM_API_KEY 才会真的走大模型；不填也能起（降级演示）
docker compose up --build          # 评测入口 :8000  网页端 :8501
docker compose exec api bash scripts/verify.sh     # 容器内一键验收（离线，dev 组已装）
```

镜像要点（见 `Dockerfile`）：

- 基础镜像 `python:3.11-slim`；依赖由 `uv.lock` 冻结、**构建期**装好；
- 合成数据库在**构建期**烘焙；compose 把 `data/` 挂成共享卷，卷为空时由
  `scripts/docker-entrypoint.sh` 本地重建（两个服务看到同一份账）；
- `.dockerignore` 排除 `.env`、本地库与缓存 —— **镜像里没有任何密钥**；
- 没配 `LLM_API_KEY` 也能起：`GET /healthz` 正常，业务查询（余额/账单/订阅）照常给真数字，
  只有需要"理解自然语言"的意图识别会降级为追问/未接通。

### 1.3 分批自查（不想起服务时）

```bash
uv run pytest -q                            # 单测
bash scripts/verify.sh                      # 一键验收（6 段，离线）
uv run python scripts/redteam.py            # 红队 30 条攻击集（stub，离线，约 1 秒）
uv run python -m interfaces.im --selftest   # IM 通道离线自检（不占端口）
uv run python scripts/api_smoke.py          # 评测入口契约冒烟（不占端口）
```

## 2. 评测入口 `POST /api/chat`

契约（字段名冻结）：

```bash
curl -s -X POST http://127.0.0.1:8000/api/chat \
  -H 'content-type: application/json' \
  -d '{"text": "查一下余额"}'
```

```json
{
  "reply": "您储蓄账户的余额是 46,634.00 元，可用余额也是 46,634.00 元（截至 2026-09-20T03:46:25）。",
  "intent": "balance_query",
  "tool_calls": ["get_balance"],
  "tier": null,
  "executed": false,
  "trace_id": "trace-00396b34d9ad"
}
```

| 字段 | 含义 |
| --- | --- |
| `reply` | 给用户的中文回执（数字全部来自本次工具的**事实包**） |
| `intent` | 规格 §3 的意图名（`unsafe_request` = 命中注入规则被拒答） |
| `tool_calls` | 本次实际调用过的白名单工具名（可空） |
| `tier` | 写操作的权限档 `L0`–`L3`（只读为 `null`） |
| `executed` | **只有**工具层真的执行成功才为 `true`（L1/L2 只出确认卡时为 `false`） |
| `trace_id` | 本次请求的审计主键（`audit_log` 里可按它展开每一步） |

补充口径：

- 可选字段 `session_id`：多轮操作（确认卡 / 短信验证码）靠它隔离会话；不传也能跑单轮。
- 请求文本按**第一方通道**处理（与网页端一致）：这类通道不套 `<untrusted_data>` 外壳；
  第三方通道（IM）才需要，见 `agent/channel.py` 与 `interfaces/im/README.md`。
- 幂等与写入：写操作走 `preview_* → 权限档 → 确认/OTP → 幂等执行`，重复调用同一 `preview_token` 返回同一结果。

## 3. 离线行为矩阵

| 环境 | 起服务 | 业务查询（余额/账单/订阅…） | 自然语言意图识别 | 写操作 |
| --- | --- | --- | --- | --- |
| 有 `LLM_API_KEY` + 有网 | ✅ | ✅ 真数字 | ✅ 走 DeepSeek | ✅ 全流程含 OTP |
| 有 key，但网络不通 | ✅ | ✅ 真数字（工具层不依赖外网） | 降级：`LLMUnavailable` → 追问/未接通，不编意图 | 不会误执行（无意图就不会进写路径） |
| 无 key | ✅ | ✅ 真数字 | 同上降级 | 同上 |
| 一键验收 `verify.sh` | — | — | 用**假 LLM**（确定性、离线） | 用假 LLM + 真工具 |

## 4. 一键验收 `verify.sh` 的 6 段

| 段 | 内容 | 失败即 |
| --- | --- | --- |
| 1/6 | 依赖与环境（`uv sync` 兜底；本地库不存在则造合成数据） | 退出码 1 |
| 2/6 | 单元测试（`pytest`） | 退出码 1 |
| 3/6 | 评测用例 `tests/cases/*.yaml`（打印用例通过率） | 退出码 1 |
| 4/6 | 冒烟对话（`app/cli.py` 未实现 → SKIP） | 退出码 1 |
| 5/6 | 红线检查（注入检测 + 数字校验器） | 退出码 1 |
| 6/6 | 红队攻击集 + IM 通道自检 + 评测入口冒烟（**全离线、不占端口**） | 退出码 1 |

## 5. 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | DeepSeek / 空 / `deepseek-chat` | 意图识别与措辞润色；**缺 key 即降级** |
| `DB_PATH` | `var/bank.db` | SQLite 合成库位置（数据目录 `var/`；代码目录 `data/` 不挂卷） |
| `DEMO_OTP` | `123456` | 演示用短信验证码（规格 §5）；**真正比对在 `tools/transfer.py`** |
| `API_HOST` / `API_PORT` | `127.0.0.1` / `8000` | 评测入口监听（容器里设 `0.0.0.0`） |
| `IM_HOST` / `IM_PORT` | `127.0.0.1` / `8090` | IM 通道监听 |
| `IM_BOT_WEBHOOK` / `IM_BOT_SECRET` / `IM_VERIFICATION_TOKEN` | 空 | 飞书机器人出消息 / 签名 / 事件订阅 token；留空即回环演示 |

`.env` 不进 git；`.env.example` 只有变量名与空值。**任何地方都不回显密钥**（`/healthz`、日志、`--guide` 都不打印）。

## 6. 常见问题

- **`uv: command not found`**：`curl -LsSf https://astral.sh/uv/install.sh | sh`（或 `pipx install uv`）。
- **端口被占**：`API_PORT=8010 uv run python -m interfaces.api`（IM/Streamlit 同理）。
- **回执变成"未接通/请补充信息"**：多半是没配 `LLM_API_KEY`（或网络不通）→ 意图识别降级，这是**设计行为**，不是崩。
- **转账要验证码，验证码是多少**：规格 §5 demo 固定 6 位，值在 `tools/transfer.py`；界面与 IM 通道都**不知道**它。
- **容器里想真的走大模型**：把 key 放进 `.env`（compose 会读），**不要**写进 `docker-compose.yml` 或 Dockerfile。
- **老版本 compose** 报 `env_file` 语法错：删掉两个服务的 `env_file:` 段，改用 `docker compose --env-file .env up`。
