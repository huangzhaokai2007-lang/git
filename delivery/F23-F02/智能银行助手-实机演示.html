2工程铁律（金融 Agent 防幻觉设计）

① 金额一律整数分 — 全程不出现 float，杜绝浮点误差吞钱
② LLM 不参与任何计算 — 金额、占比、异常判定全部由整数运算决定，LLM 只润色措辞
③ 回执数字必须来自 facts — VERIFY_NUMBERS 状态逐字校验，出现 facts 之外的数字 → 降级模板回执 + HALLUCINATION_BLOCKED
④ 错误消息不含数字 — 回执里的每个数字都能在 facts 里找到出处
⑤ 归属断言防越权 — DAO 不按 user 圈定（风险已登记台账），工具层显式断言归属，越权 → FORBIDDEN
⑥ 每请求一条审计 — trace_id 贯穿，AUDIT 状态落库，写审计失败只记日志不影响回执
⑦ 时间解析走代码 — "上个月"由 period.py 解析（锚点 2026-09-12），认不出就追问，绝不静默猜
⑧ 只读路由无写操作 — 转账/挂失/取消订阅等写意图不进 EXECUTE，测试静态红线钉死

3交互式对话设计（v2 核心 + v3 细节层 · 每个交互都有产品与工程理由）

💳 银行卡 → PIN 验证 → 翻卡查余额
回复框内渲染立体卡片，点击任意一张卡唤起数字键盘 PIN 验证（演示 PIN 123456），验证通过卡片 3D 翻转展示该卡余额与限额；连错 3 次临时锁定。 工程理由：guard/permission.py 的权限档位（audit_log.permission_tier 字段）目前为 L0 占位——本交互是 L1「验证后可查」档位的产品化预演；每次验证尝试（无论成败）均落审计日志。
📋 流水行点击 → 展开交易详情
流水表每一行可点击，展开该笔交易的完整信息：完整时间戳（含秒）、整数分原始金额、对方、分类、渠道。 工程理由：把「金额一律整数分」铁律①变成看得见的东西——列表显示元、详情显示分，用户能亲眼核对换算。
📊 分类条形点击 → 下钻该分类当月明细
账单分析页每条分类占比条可点击，展开该分类当月全部交易与小计，小计与总览条形数字严格一致。 工程理由：下钻明细由页面端从同一次采集的全月流水（list_txn 2026-08-01→08-31）聚合，聚合结果与 analyze_spending 工具输出互证——数据不是编的，是同一份事实的两个视图。
🎵 订阅卡片 → 取消订阅 → 安全拦截
每个订阅带「取消订阅」按钮，点开确认层后选择确认——随即被写操作安全策略拦截并落审计。 工程理由：铁律⑧「只读路由无写操作」的主动式演示——按钮真实存在（像真实产品），但执行层没有写通道，用户亲手触发一次拦截比看一百句描述更有说服力。
📈 余额卡片 → 每日收支趋势
余额卡片内嵌「查看 2026-08 每日收支趋势」，展开 31 天双柱迷你图（支出红 / 收入绿）。 工程理由：趋势图由全月 31 笔真实流水按日聚合渲染，每根柱都可溯源到真实交易——图表不引入任何 facts 之外的数字。
💡 建议操作（Suggested Actions）
每条回复底部附「您可能想」快捷入口，一键续接下一查询（查完余额→看流水→下钻分类→异常检测）。 产品理由：对话式 UI 的引导性——用户不必知道"该问什么"，Agent 主动给出下一步；同时把 11 个场景串成自然的探索路径。
🔔 通知中心（v3）
聊天窗右上角铃铛聚合提醒（未读徽标）：异常交易提醒、订阅扣费预告——点击直达对应查询场景，阅读行为落审计。 工程理由：通知内容全部来自已采集 facts（detect_anomalies 的 8 笔、list_subscriptions 的扣费日期/金额）——通知不引入任何 facts 之外的数字。
🔍 流水筛选与搜索（v3）
流水表支持「全部/支出/收入」方向筛选 + 对方/分类/渠道关键词过滤，合计随当前视图实时聚合并明示标注。 工程理由：筛选合计由页面端对同一份 TXN_ITEMS 聚合——与回执 facts 同源的第二视图，"全部"视图下合计与回执逐字一致。
🧾 异常申诉 → 争议工单（v3）
异常交易每行可点「申诉」→ 确认 → 工单创建（编号 + 转人工说明），诉求与工单号落审计。 产品理由：只读 Agent 的正确"写"姿势——用户诉求被记录并转人工，而非硬编一个"已处理"；页面明示工单流为产品化预演（写路径未接通），诚实优先。
⚡ 实时意图识别 + 会话统计（v3）
输入框打字即时显示 intent / 置信度 / 将执行的场景（低置信度时预告"会追问"）；聊天窗头部实时显示轮次、工具调用、审计条数计数器。 工程理由：意图识别复刻交付代码 classifier 的关键词规则与判定顺序（置信度取真实采集值）；统计计数让「每请求一条审计」从口号变成看得见的数字。
📊 银行 App 质感三件套 + 操作条（v3）
金额数字滚动入场（终值精确 = facts）；小眼睛遮罩防偷看（状态落审计）；信用卡额度使用率条（页面端由欠款÷授信计算）；每条回复可复制 / 语音播报（TTS）/ 👍👎 反馈（落审计）。 工程理由：count-up 动画的每一帧都是整数分插值、终值与 facts 逐字一致；反馈与遮罩等交互事件全部进入审计——"所见即所审"贯彻到像素级。
